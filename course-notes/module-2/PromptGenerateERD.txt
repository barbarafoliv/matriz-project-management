# ROLE
Act as a Database Architect specialising in data modelling and technical documentation.

# GOAL
Generate an Entity-Relationship Diagram (ERD) in Mermaid, based on the previously approved data model for the Matriz application.

# CONTEXT
The data model was analysed and validated in the previous step.

Use as reference:
- The approved model of entities and attributes.
- The table of relationships and cardinalities.
- The defined integrity rules.
- The documented modelling decisions.

Consult docs/database.md, if it contains the approved model. Otherwise, use the model approved in this conversation.

If you don't have access to the validated model, ask for it before generating the diagram.

# CONSTRAINTS
- Use only approved entities and relationships.
- Don't add arbitrary features or entities.
- Don't change cardinalities without justification and approval.
- Represent primary and foreign keys where defined.
- Use the Mermaid erDiagram syntax.
- Keep names consistent with the model.
- Avoid technology details that haven't been defined.
- Don't generate SQL or migrations.
- Don't change files without approval.

# TASKS

1. Identify all the entities in the approved model.

2. Represent their attributes, identifiers and references.

3. Represent the relationships with the correct cardinalities and whether they are mandatory.

4. Identify the associative entities needed for N:M relationships.

5. Generate the ERD using Mermaid.

6. Review how the diagram matches the approved model.

7. Identify any inconsistencies or decisions that still need human validation.

# OUTPUT FORMAT

1. Complete ER diagram in Mermaid.
2. Table of the relationships represented.
3. Identification of primary and foreign keys.
4. Notes on ambiguities or limitations.

# VALIDATION
Check:
- All approved entities are represented.
- All approved relationships are represented.
- The cardinalities are correct.
- The foreign keys are consistent.
- No unapproved entities were introduced.
- The code follows the Mermaid erDiagram syntax.

If you have access to a Mermaid renderer, validate the rendering and fix any errors.

If you can't run the validation, state explicitly that it is still pending.

Present the diagram for review before moving on to the physical implementation of the database.
