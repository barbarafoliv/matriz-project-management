# Matriz 1.1.0-rc.1 (release candidate)

**Date:** 2026-11-18 · **Previous version:** [1.0.0](https://github.com/barbarafoliv/matriz-project-management/releases/tag/v1.0.0) · **Changes:** [CHANGELOG.md](../../CHANGELOG.md)

This candidate prepares Matriz for delivery. It can be built, tested and run the same way on any machine with Docker, every change is checked automatically, and it is available online. No features change. The REST API has the same endpoints and data ([openapi.yaml](../openapi.yaml), version 1.0.0); its rules for spaces and lengths are described more precisely, and it lists the online address.

## Why 1.1.0-rc.1

- **Minor version (1.1.0):** new, backward-compatible ways to build, run and deploy the application, plus fixes. Nothing that worked in 1.0.0 stops working, and the API has the same endpoints. So it isn't a major version.
- **Release candidate (`-rc.1`):** published for validation (Worksheet 05, Exercise 6). If no blocking problem is found, the same code becomes 1.1.0.

## Highlights

- **Docker Compose:** `docker compose up -d` starts the database, backend and frontend on http://localhost:4200, each after the previous one is healthy.
- **Continuous integration:** GitHub Actions runs on every push and pull request:
  - backend tests and SpotBugs;
  - frontend lint, tests and build;
  - the end-to-end test.

  It then builds the Docker images. The pipeline fails when a test fails, and the images are then not built.
- **Online:** https://matriz-c1ft.onrender.com, on Render and Neon. It is deployed after CI passes, and its cookies are only sent over HTTPS.
- **Fixes since 1.0.0:**
  - lengths count characters, not UTF-16 units;
  - text made only of Unicode spaces is rejected;
  - account deletion ends sessions only after it is saved;
  - `./mvnw` works on Linux and macOS;
  - two requests at the same moment to add or assign the same member no longer both report success.

## Upgrading from 1.0.0

- `docker compose up -d` now starts the whole application. For development with `./mvnw spring-boot:run` and `npm start`, start only the database: `docker compose up -d db`.
- No database change is needed. Liquibase finds the existing changesets and runs none, so existing data is kept.
- No new variables are needed in `.env`. `COOKIES_SECURE` is only set online.

## Known limitations

- The free Render backend sleeps after about 15 minutes without requests; the next request takes about a minute.
- Online, the demo accounts use the public demo password, so anyone can change the demo data.
- There is one end-to-end scenario, and it runs only in Chromium.
- Open findings, all Low (details in [quality-security-review.md](../quality-security-review.md), section 7, and [verification.md](../verification.md), section 5):
  - findings that need two requests at the same moment, including the failed sign-in counter (F10);
  - behind nginx and Render, the `Location` header of 201 responses points to the backend's own address; the frontend doesn't use it (F11);
  - `npm audit` reports 24 high advisories in development tools only, through `picomatch`, which has no fixed version yet (F12). The delivered app has 0.
